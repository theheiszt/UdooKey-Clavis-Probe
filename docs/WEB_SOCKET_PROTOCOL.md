# UDOO KEY — WebSocket Protocol Specification

## 1. Overview

The UDOO KEY ESP32 coprocessor hosts an asynchronous WebSocket endpoint on:

```text
ws://192.168.4.1/ws
```

The WebSocket link provides a low-latency, bidirectional transport between client web browsers and the instrument hardware. It handles:
- Asynchronous acquisition control (`arm`, `single`, `stop`).
- Hardware configuration parameters (sample rate, sample depth, trigger channel, trigger mode, pre-trigger ratio).
- High-speed binary capture streaming with embedded framing headers.
- Real-time diagnostic telemetry, analog ADC voltages, and Bit Pirate CLI terminal streaming.

---

## 2. Frame Types & Data Representation

The WebSocket connection handles two distinct frame formats:
1. **Text Frames (JSON / UTF-8)**: Used for control messages, telemetry queries, and terminal output.
2. **Binary Frames (`ArrayBuffer`)**: Used exclusively for transferring logic analyzer capture buffers.

---

## 3. Client $\rightarrow$ Server JSON Commands

All client commands are formatted as JSON text frames containing a required `"cmd"` field:

### 3.1 Arm Acquisition (`arm` / `start`)
Initiates logic acquisition on the RP2040 engine.
```json
{
  "cmd": "arm",
  "rate": 10000000,
  "count": 8192,
  "trigger_channel": 0,
  "trigger_mode": 1,
  "pre_trigger_pct": 70
}
```
- `rate` *(uint32)*: Requested sample rate in Hz (100,000 to 100,000,000). Default: `10000000`.
- `count` *(uint32)*: Requested buffer size (1,024 to 65,536). Default: `8192`.
- `trigger_channel` *(uint8)*: Channel index 0..7 (`GP2`..`GP9`) or 10 (`EXT_TRIG GP10`). Default: `0`.
- `trigger_mode` *(uint8)*:
  - `0`: Auto / Immediate
  - `1`: Rising Edge
  - `2`: Falling Edge
  - `3`: Any Edge
  - `4`: High Level
  - `5`: Low Level
- `pre_trigger_pct` *(uint8)*: Pre-trigger buffer allocation percentage (0..100). Default: `70`.

### 3.2 Single Shot Capture (`single`)
Identical to `arm`, instructing the client to remain in single-shot mode without re-arming.
```json
{
  "cmd": "single",
  "rate": 10000000,
  "count": 8192,
  "trigger_channel": 0,
  "trigger_mode": 1,
  "pre_trigger_pct": 70
}
```

### 3.3 Stop Acquisition (`stop`)
Aborts ongoing sampling immediately.
```json
{
  "cmd": "stop"
}
```

### 3.4 Query Instrument Status (`status`)
Queries the state of the RP2040 engine and ESP32 coprocessor.
```json
{
  "cmd": "status"
}
```

### 3.5 Request Recent Capture (`get_capture`)
Requests re-transmission of the most recently acquired binary capture buffer.
```json
{
  "cmd": "get_capture"
}
```

### 3.6 PWM Signal Generator (`set_pwm`)
Configures the hardware PWM output pin on ESP32 IO25.
```json
{
  "cmd": "set_pwm",
  "freq": 1000,
  "duty": 50
}
```

### 3.7 Terminal Command (`term`)
Sends a raw command string to the Bit Pirate CLI execution engine.
```json
{
  "cmd": "term",
  "text": "scan"
}
```

## 4. Server $\rightarrow$ Client JSON Responses

### 4.1 Status Response (`status_resp`)
Sent on initial WebSocket connection and in response to `"cmd": "status"`.
```json
{
  "type": "status_resp",
  "state": "IDLE",
  "rate": 10000000,
  "samples": 8192,
  "trigger_offset": 5734,
  "capture_id": 42,
  "adc0": 1650,
  "adc1": 3290,
  "adc2": 0
}
```
- `state`: String indicating current state (`"IDLE"`, `"ARMED"`, `"TRIGGERED"`, `"READY"`, `"STOPPED"`).
- `rate`: Configured sample rate in Hz.
- `samples`: Number of valid samples in the buffer.
- `trigger_offset`: Index where the trigger condition was met.
- `adc0..2`: Analog channel readings in millivolts (mV).

### 4.2 Capture Notification (`capture_ready`)
Sent immediately after a capture buffer has been reassembled from the RP2040.
```json
{
  "type": "capture_ready",
  "capture_id": 42,
  "rate": 10000000,
  "samples": 8192,
  "trigger_offset": 5734
}
```

### 4.3 Trigger Notification (`trigger_fired`)
Emitted as soon as the hardware trigger event occurs.
```json
{
  "type": "trigger_fired",
  "channel": 0,
  "timestamp_us": 14920482
}
```

### 4.4 Terminal Output Stream (`term`)
Streams text output generated by the RP2040 or ESP32 diagnostic commands.
```json
{
  "type": "term",
  "text": "\n[I2C Scan] Discovered device at 0x68\n> "
}
```

---

## 5. Server $\rightarrow$ Client Binary Frames

When a capture is transmitted to the browser, it is packaged as a binary WebSocket frame composed of:
1. A **32-byte `WebLogicCaptureHeader`** containing all acquisition metadata.
2. Followed immediately by $N$ bytes of raw packed 8-bit sample data.

Detailed specifications for binary unpacking are defined in `docs/LOGIC_CAPTURE_FORMAT.md`.
